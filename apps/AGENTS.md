# BECA app design and interaction rules

Follow the root `agents.md` technical workflow and the [instrument UI rules](../docs/design/INSTRUMENT_UI.md) and [copy rules](../docs/design/UI_COPY.md). These instructions apply to all phone, Apple and desktop app sources in this directory.

- Build a playable instrument: modes, presets, master, play and panic come first. Group sound controls by synthesis stage. Keep setup, network, routing and diagnostics secondary.
- Show controls only in modes that use them. Shared pitch/timing controls remain where the firmware actually uses them. Apply visibility to initial state, local gestures and device updates. Preserve hidden values.
- Keep plant scope and MIDI feedback visible and stable. Do not show fabricated signal/note animation.
- Use functional musical labels and short actionable states. Remove slogans, dashboard filler, assistant narration and repeated how-to paragraphs from performance views. Run `python3 tools/check_ui_copy.py` from the repository root.
- Use consistent spacing, small radii, monochrome surfaces and green accents only. Setup may retain the light utility surface. Keep keyboard focus, touch targets, contrast, and 360 px layouts usable.
- Preserve source MIDI pitch/channel/velocity and note-off behavior. Browser Wi-Fi sound must not re-arpeggiate a sequence already generated by BECA.
- Coalesce parameter writes, diff UI state, bound queues/polling, and panic on stream loss, disconnect, interruption and backgrounding. Keep firmware targeting ESP32 core 2.0.14 without BLE library changes.
- Every design change needs interaction checks and a screenshot review on phone, tablet and desktop where applicable. Test audio/transport changes beyond screenshots. Report physical-device checks separately.
- Rebuild phone/Apple resources, generated device player assets and desktop executables/installer artifacts that changed. Preserve existing user edits. Do not silently replace published releases.

Use four review roles: instrument designer (workflow/mode map), interaction reviewer (touch/keyboard/layout), audio/transport reviewer (timing/note-off/recovery), and copy editor (functional language). When delegation is requested, give each agent a disjoint implementation area and integrate/test the complete result.
